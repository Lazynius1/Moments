3) BACKEND-FIRST FEED (4-7 días, impacto máximo)
--------------------------------------------------

IDEA CLAVE
La lógica de audiencia se ejecuta en Cloud Functions/backend.
El cliente recibe feed ya filtrado.

Flujo:
1. Cliente llama endpoint: getFeedPage(cursor, feedType, limit).
2. Backend construye viewerContext:
   - following, followers, mutuals, bestFriends, customLists.
3. Backend toma candidatos de moments.
4. Aplica canViewerSeeMoment(...) en servidor.
5. Devuelve solo items visibles + nextCursor.
6. Cliente pinta sin hacer validación N+1 por item.
Estado: [x] Hecho.
- [x] getFeedPage en backend con filtro de privacidad server-side.
- [x] Cliente backend-first en following + forYou + loadMore con fallback legacy.
- [x] Cursor compuesto (timestamp + momentId + authorId) y dedupe por ref.path.
- [x] Fail-closed si falta authorDoc.
- [x] Advance cursor cuando una página queda vacía por filtros de privacidad.
- [x] Ajuste fino de paginación y límites (fetchLimit=80 para Following).
- [x] Cierre de validación E2E exitoso (paridad verificada missing_in_backend=0).

Beneficios:
- Menos queries por pantalla.
- Menor trabajo en main thread.
- Mejor scroll/percepción de velocidad.
- Mayor consistencia de reglas de visibilidad.

IMPORTANTE
- Seguridad real sigue en Firestore Rules + backend.
- El cliente no debe tener libertad para leer feed crudo sin filtro.
